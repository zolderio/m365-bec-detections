# T1114.003 — Email Forwarding Rule

| | |
|---|---|
| **MITRE-tactiek** | Collection |
| **Whitepaper-maatregel** | 016 — Blokkering van automatische e-mailforwarding (prioriteit Hoog) |
| **Verwante techniek** | [T1564.008](T1564.008-email-hiding-rules.md) — dezelfde events, ander doel |
| **Status van deze detectie** | KQL niet uitgevoerd tegen een productie-tenant — zie [TESTING.md](../TESTING.md) |

## Aanbeveling

> ### `SENTINEL-RULE` — bouw hier een eigen analytic rule
>
> Het Defender-alert bestaat en vereist géén E5, maar dekt de handeling niet
> volledig: regels die vanuit de Outlook-desktopclient worden aangemaakt vallen
> erbuiten, en juist die zijn voor de beheerder het slechtst zichtbaar. Zet het
> alert wél aan als vangnet en verhoog de severity van Informational naar
> minimaal Medium — dat kan zonder extra licentie — maar leun er niet op voor
> de dekking.

## Is er een Defender-alert voor?

**Deels.** Er bestaat een standaard alert policy, maar met twee beperkingen die
bepalen of je er detectie op kunt bouwen.

| | |
|---|---|
| **Alert policy** | `Creation of forwarding/redirect rule` |
| **Standaard severity** | **Informational** |
| **Licentie** | E1/F1/G1, E3/F3/G3 of E5/G5 — geen add-on nodig |
| **Beperking 1** | Microsoft: *"This policy only tracks inbox rules that are created using Outlook on the web (formerly known as Outlook Web App) or Exchange Online PowerShell."* Een regel uit de Outlook-desktopclient levert **geen** alert op. |
| **Beperking 2** | De policy dekt alleen regels die forwarden of redirecten. Een regel die mail alleen verplaatst of verwijdert valt eronder noch onder een andere policy — zie T1564.008. |
| **Bron** | https://learn.microsoft.com/en-us/defender-xdr/alert-policies |

Een gerelateerde policy met een bruikbaarder niveau:

| | |
|---|---|
| **Alert policy** | `Suspicious email forwarding activity` |
| **Standaard severity** | **High** |
| **Licentie** | E1/F1/G1, E3/F3/G3 of E5/G5 |
| **Wat het is** | Vuurt niet op het aanmaken van de regel, maar heuristisch op verzonden mail naar een verdacht extern account. Detecteert dus pas nadat er data weg is. |

Vervallen, niet meer op bouwen: de Defender for Cloud Apps-policy
`Suspicious inbox forwarding` is per juni 2025 als legacy policy uitgezet.
Bron: https://learn.microsoft.com/en-us/defender-cloud-apps/anomaly-detection-policy

## Benodigde databron

| Platform | Tabel | Wat er onboard moet zijn |
|---|---|---|
| Microsoft Sentinel | `OfficeActivity` | Data connector **Microsoft 365** (Exchange-workload aan). Vereist een ingeschakelde Unified Audit Log — whitepaper-maatregel 012. |
| Defender XDR advanced hunting | `CloudAppEvents` | Geen connector; standaard beschikbaar bij Defender for Cloud Apps-integratie. Retentie 30 dagen. |

Zonder maatregel 012 (UAL aan) leveren beide queries niets op. Dat is geen
detectieprobleem maar een logging-probleem.

## KQL — Sentinel (OfficeActivity)

```kql
// Aangemaakte of gewijzigde inboxregel met een forward-, redirect- of
// forward-as-attachment-actie. Dekt bewust ook UpdateInboxRules, want dat is
// de operation die de Outlook-desktopclient schrijft en waar de standaard
// alert policy niet op vuurt.
let lookback = 7d;
OfficeActivity
| where TimeGenerated > ago(lookback)
| where Operation in~ ("New-InboxRule", "Set-InboxRule", "UpdateInboxRules")
| extend RuleParameters = tostring(Parameters)
| where RuleParameters has_any ("ForwardTo", "ForwardAsAttachmentTo", "RedirectTo")
| extend TargetAddress = extract(@"(?i)(?:ForwardTo|ForwardAsAttachmentTo|RedirectTo)""?,""?Value""?:""?\[?([^""\]]+)", 1, RuleParameters)
| project TimeGenerated, UserId, Operation, ClientIP, TargetAddress, RuleParameters, OriginatingServer
| order by TimeGenerated desc
```

## KQL — Defender XDR advanced hunting (CloudAppEvents)

```kql
let lookback = 7d;
CloudAppEvents
| where Timestamp > ago(lookback)
| where ActionType in~ ("New-InboxRule", "Set-InboxRule", "UpdateInboxRules")
| extend Params = tostring(RawEventData.Parameters)
| where Params has_any ("ForwardTo", "ForwardAsAttachmentTo", "RedirectTo")
| project Timestamp, AccountDisplayName, AccountObjectId, ActionType, IPAddress, Params
| order by Timestamp desc
```

## Aanscherpen op extern

Forwarding naar een intern adres is meestal legitiem. Vervang in beide queries
de laatste filterregel om alleen externe bestemmingen over te houden:

```kql
| extend TargetDomain = tolower(tostring(split(TargetAddress, "@")[1]))
| where isnotempty(TargetDomain)
| where TargetDomain !in~ ("eigendomein.nl", "eigendomein.com")   // <-- aanpassen
```

## Waarom dit BEC is

De aanvaller leest mee zonder opnieuw in te loggen, en de regel overleeft een
wachtwoordwijziging en een MFA-reset. CISA beschrijft uit eigen
incidentonderzoek regels die inkomende waarschuwingen naar de map *RSS
Subscriptions* verplaatsen zodat het slachtoffer ze niet ziet (AR21-013A,
januari 2021). De FBI waarschuwde in november 2020 dat regels gemaakt in de
webclient niet syncen met de desktopclient en daardoor onzichtbaar blijven voor
de beheerder (PIN 20201125-001).
