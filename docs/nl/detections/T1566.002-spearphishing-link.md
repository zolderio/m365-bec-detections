# T1566.002 — Spearphishing Link

| | |
|---|---|
| **MITRE-tactiek** | Initial Access |
| **Whitepaper-maatregelen** | 004 — Phishing-resistente multifactorauthenticatie (prioriteit Hoog)<br>005 — Microsoft Defender for Office 365 (prioriteit Midden) |
| **Verwante technieken** | [T1557](T1557-adversary-in-the-middle.md) — waar de link meestal naartoe leidt<br>[T1598](T1598-phishing-for-information.md) — dezelfde mailstroom, maar zonder payload |
| **Status van deze detectie** | KQL niet uitgevoerd tegen een productie-tenant — zie [teststatus](../teststatus.md) |

## Aanbeveling

> ### `DEFENDER-ALERT + SENTINEL-RULE` — beide
>
> Dit is de techniek waar Microsoft de beste standaard dekking voor levert:
> `A potentially malicious URL click was detected` en
> `A user clicked through to a potentially malicious URL` staan allebei op
> **High** en triggeren automatisch onderzoek. Zet ze aan. Maar allebei vereisen
> ze E5/G5 of de Defender for Office 365 Plan 2 add-on, allebei werken ze alleen
> met Safe Links, en allebei hangen ze aan een *verdict*: de URL moet als
> kwaadaardig herkend zijn. Een AiTM-proxy op een domein dat een uur oud is
> heeft dat verdict nog niet, en dat is precies het geval waar het bij BEC om
> draait. De Sentinel-rule dekt de klik zonder verdict.

## Is er een Defender-alert voor?

**Ja, twee — en dit keer op een niveau waar iemand naar kijkt.**

| | |
|---|---|
| **Alert policy** | `A potentially malicious URL click was detected` |
| **Standaard severity** | **High** |
| **Licentie** | E5/G5 of Defender for Office 365 Plan 2 add-on |
| **Wat het is** | Vuurt wanneer een door Safe Links beschermde gebruiker op een kwaadaardige link klikt en dat een *URL verdict change* oplevert. Kijkt bovendien 48 uur terug vanaf het moment dat het verdict verandert, en genereert alsnog alerts voor kliks in dat venster. Triggert automatisch AIR in Defender for Office 365 Plan 2. |
| **Beperking** | Geen verdict, geen alert. Vers geregistreerde phishinginfrastructuur ontsnapt daaraan tot het verdict er is. |
| **Bron** | https://learn.microsoft.com/en-us/defender-xdr/alert-policies |

| | |
|---|---|
| **Alert policy** | `A user clicked through to a potentially malicious URL` |
| **Standaard severity** | **High** |
| **Licentie** | E5/G5 of Defender for Office 365 Plan 2 add-on |
| **Wat het is** | Vuurt wanneer de gebruiker de Safe Links-waarschuwingspagina wegklikt met *Continue anyway* en de URL alsnog opent. |
| **Beperking** | Alleen bij een expliciete doorklik; en alleen als het anti-phishingbeleid de waarschuwingspagina laat zien. |

Twee policies die er vlak achteraan komen, met een lager niveau:

| Alert policy | Severity | Licentie | Rol |
|---|---|---|---|
| `Email messages containing malicious URL removed after delivery` | **Informational** | E3/G3, Microsoft 365 Business Premium, MDO Plan 1 add-on, E5/G5, of MDO Plan 2 add-on | ZAP heeft het bericht achteraf weggehaald. Nuttig, maar `Informational`. Ophogen is bij een System-policy niet aantoonbaar mogelijk — zie [severity van een ingebouwde policy](../index.md#kun-je-de-severity-van-een-ingebouwde-policy-ophogen). |
| `Messages containing malicious entity not removed after delivery` | **Medium** | idem | ZAP heeft het geprobeerd en het is misgegaan. Dit is de ernstiger van de twee en staat toch lager dan de kliks. |

Let op: `Email messages containing phish URLs removed after delivery` bestaat
nog, maar Microsoft heeft die policy vervangen door
`Email messages containing malicious URL removed after delivery` en adviseert de
oude uit te zetten. Bouw er niets nieuws op.

**Randvoorwaarde, geen detail.** Safe Links zit in Defender for Office 365
Plan 1; advanced hunting op `UrlClickEvents` zit in Plan 2. Met alleen EOP is er
noch een alert, noch een tabel.

## Benodigde databron

| Platform | Tabel | Wat er onboard moet zijn |
|---|---|---|
| Microsoft Sentinel | `UrlClickEvents`, `EmailEvents` | Data connector **Microsoft Defender XDR**, *Connect events* → Defender for Office 365-tabellen aanvinken. |
| Defender XDR advanced hunting | `UrlClickEvents`, `EmailEvents` | Defender for Office 365 uitgerold; **advanced hunting vereist Plan 2**. Safe Links moet aanstaan, anders blijft `UrlClickEvents` leeg. |

Niet afhankelijk van maatregel 012 (UAL).

Eén valkuil bij het koppelen van klik aan bericht: voor kliks op mail in
Concepten en Verzonden items is de e-mailmetadata er niet of krijgt
`NetworkMessageId` een standaardwaarde. Die records kun je dus **niet** op
`NetworkMessageId` joinen met `EmailEvents`.

## KQL — de klik zonder verdict (beide platforms)

`UrlClickEvents` heeft in Sentinel en in advanced hunting dezelfde kolomnamen.

<!-- query
platform: both
name: Safe Links click with no threat verdict on first-contact mail from an external sender
technique: T1566.002
severity: Medium
tactics: [InitialAccess]
interval: PT1H
lookback: P7D
parameters: [ownDomains]
deployable: true
-->

```kql
// Kliks waar de filterstack op het moment van klikken geen dreiging zag. Dit is
// precies de verzameling die geen enkel Defender-alert oplevert. Het filter op
// eerste contact en op een externe afzender maakt er iets bruikbaars van: de
// combinatie "onbekende afzender + klik op een link" is de instap van vrijwel
// elke AiTM-campagne.
let lookback = 7d;
let ownDomains = dynamic(["yourdomain.example", "yourseconddomain.example"]);   // <-- aanpassen
let firstContact =
    EmailEvents
    | where Timestamp > ago(lookback)
    | where EmailDirection == "Inbound"
    | where IsFirstContact == 1
    | where SenderFromDomain !in~ (ownDomains)
    | project NetworkMessageId, SenderFromAddress, SenderFromDomain, Subject,
              EmailDeliveryAction = DeliveryAction;
UrlClickEvents
| where Timestamp > ago(lookback)
| where Workload == "Email"
| where isempty(ThreatTypes)          // geen verdict op het moment van klikken
| join kind=inner firstContact on NetworkMessageId
| project Timestamp, AccountUpn, Url, UrlChain, ActionType, IsClickedThrough,
          SenderFromAddress, SenderFromDomain, Subject, EmailDeliveryAction,
          IPAddress, NetworkMessageId, ReportId
| order by Timestamp desc
```

### Doorgeklikt ondanks de waarschuwing

Onderstaande query staat zo in de Microsoft-documentatie van de tabel.

<!-- query
platform: both
name: User clicked through the Safe Links warning page to a phishing URL
technique: T1566.002
severity: High
tactics: [InitialAccess]
interval: PT1H
lookback: P1D
parameters: []
deployable: true
-->

```kql
// Search for malicious links where user was allowed to proceed through
UrlClickEvents
| where ActionType == "ClickAllowed" or IsClickedThrough !="0"
| where ThreatTypes has "Phish"
| summarize by ReportId, IsClickedThrough, AccountUpn, NetworkMessageId, ThreatTypes, Timestamp
```

De volledige waardenlijst van `ActionType` staat **niet in de
schemadocumentatie**; `ClickAllowed` is de enige waarde die Microsoft daar
noemt. Stel de rest vast met de ingebouwde schemareferentie in het
Defender-portaal voordat je erop filtert.

### Meerdere ontvangers, dezelfde URL

Gerichte phishing komt zelden in één exemplaar binnen. Deze query zoekt de
campagne in plaats van het bericht.

<!-- query
platform: both
name: Same URL clicked by multiple recipients within one week
technique: T1566.002
severity: Medium
tactics: [InitialAccess]
interval: PT1H
lookback: P7D
parameters: []
deployable: true
-->

```kql
let lookback = 7d;
UrlClickEvents
| where Timestamp > ago(lookback)
| where Workload == "Email"
| summarize Clicks         = count(),
            Clickers       = dcount(AccountUpn),
            Who            = make_set(AccountUpn, 30),
            ClickedThrough = countif(IsClickedThrough),
            First          = min(Timestamp),
            Last           = max(Timestamp)
          by Url
| where Clickers >= 3
| order by Clickers desc
```

### De bezorgde berichten waar niemand op klikte

Blinde vlek bij het opschonen na een campagne: de mails die zijn bezorgd maar
(nog) niet zijn aangeklikt.

<!-- query
platform: both
name: Phishing mail delivered to the inbox that nobody clicked yet
technique: T1566.002
severity: Medium
tactics: [InitialAccess]
interval: PT1H
lookback: P7D
parameters: []
deployable: true
-->

```kql
let lookback = 7d;
let clicked = UrlClickEvents | where Timestamp > ago(lookback) | distinct NetworkMessageId;
EmailEvents
| where Timestamp > ago(lookback)
| where EmailDirection == "Inbound"
| where ThreatTypes has "Phish"
| where DeliveryLocation == "Inbox/Folder"    // bezorgd, ondanks het verdict
| where NetworkMessageId !in (clicked)
| project Timestamp, RecipientEmailAddress, SenderFromAddress, Subject,
          ThreatTypes, DetectionMethods, LatestDeliveryLocation, NetworkMessageId
| order by Timestamp desc
```

`LatestDeliveryLocation` is niet beschikbaar via de Streaming API en dus mogelijk
leeg in Sentinel; in advanced hunting werkt de kolom wel.

## Waarom dit BEC is

De spearphishinglink is bij BEC bijna nooit het doel maar het scharnier: hij
levert de credentials en het sessiecookie waarmee de mailbox opengaat. Microsoft
beschreef in juni 2023 een campagne waarin de link op een legitiem
Canva-platform stond, doorlinkte naar een nagemaakte Microsoft-aanmeldpagina op
Tencent-cloud, en de aanvaller uren later met het gestolen cookie vanaf
Amerikaanse IP-adressen inlogde, een eigen MFA-methode registreerde, een
inboxregel aanmaakte en vervolgens ruim 16.000 phishingmails naar de contacten
van het slachtoffer stuurde. MITRE plaatst T1566.002 in Initial Access; in dit
advies is dat de scharnierfase tussen Credential Access en alles wat daarna in
de mailbox gebeurt.
